# 260724 Improve - Prompt Templates

## 1. 目标

沉淀一组可配置、可扩展、可版本化的 LLM 清洗模板，用于：

1. 默认自动生成首版结果
2. 手动按场景重新解析
3. 后续衍生任务抽取、复盘总结等扩展

## 2. 使用原则

1. 默认模板负责自动生成首版结果。
2. 模板切换不覆盖历史结果，而是生成新的 `meeting_llm_results` 版本。
3. 模板文本支持插槽变量，至少包括 `{transcript}`。
4. 模板内容应强调“忠于原文、不臆造、不遗漏明确行动项”。
5. 模板仅允许管理员维护。

## 3. 推荐模板列表

### `standard_minutes`

名称：标准会议纪要

适用场景：

- 日常项目会
- 周会
- 跨团队同步

目标：

- 输出均衡、结构化、适合作为默认纪要的 Markdown。

建议结构：

1. 会议主题
2. 会议摘要
3. 讨论要点
4. 关键结论
5. 待办事项
6. 风险与待确认项

### `decision_log`

名称：决策记录型

适用场景：

- 技术方案评审
- 管理层决策
- 路线选择讨论

目标：

- 提取备选方案、权衡点、最终决定和决策依据。

### `task_breakdown`

名称：任务拆解型

适用场景：

- 项目推进会
- 排期会
- 执行跟进会

目标：

- 最大化提取行动项、负责人、时间点和阻塞项。

### `client_communication`

名称：客户沟通纪要型

适用场景：

- 客户需求沟通
- 售前交流
- 交付例会

目标：

- 区分客户诉求、我方承诺、未决问题和边界风险。

### `retrospective`

名称：复盘总结型

适用场景：

- 事故复盘
- 项目复盘
- 阶段回顾

目标：

- 提取背景、过程、问题根因、影响和改进措施。

### `executive_summary`

名称：精简摘要型

适用场景：

- 高层浏览
- 邮件同步
- 周报摘要

目标：

- 将长会议内容压缩成极短摘要和少量关键点。

### `action_items_only`

名称：行动项抽取型

适用场景：

- 已有完整结果，单独抽任务
- 需要同步到任务系统

目标：

- 尽量只输出任务，而不是完整纪要。

## 4. 默认模板建议

一期建议将 `standard_minutes` 设为默认模板。

原因：

1. 通用性最好。
2. 适合录音结束后自动生成首版结果。
3. 后续如需更偏任务或决策，可通过手动重解析获得。

## 5. 默认模板示例

以下是一版建议默认模板骨架：

```text
你是一个专业的会议纪要整理助手。请基于以下会议转写内容，输出结构化的会议纪要。

要求：
1. 忠于原文，不要臆造未提及的事实、决定或任务。
2. 删除口语化重复、语气词和明显噪声。
3. 保留关键讨论、明确结论和可执行待办事项。
4. 输出使用简洁专业的中文 Markdown。
5. 如果原文没有明确结论或负责人，要明确标注“未明确”。

请按以下结构输出：

# 会议主题

# 会议摘要

# 讨论要点

# 关键结论

# 待办事项

# 风险与待确认项

会议转写内容：
{transcript}
```

## 6. 手动重解析交互建议

1. 在会议详情页提供“重新解析”入口。
2. 弹出模板选择列表，展示名称和适用场景说明。
3. 用户选择模板后生成新的 `meeting_llm_results` 版本。
4. 保留旧版本可回溯。

## 7. 模板表建议字段

建议最少包含：

- `id`
- `template_key`
- `template_name`
- `template_type`
- `content`
- `description`
- `status`
- `is_system`

说明：

1. 当前默认模板由 `app_settings` 中 `system.default_prompt_template_id` 指向。
2. 如果后续需要“禁用模板”，应建模为模板状态，而不是再引入第二套“当前启用”真相源。
3. 被历史结果引用过的模板不应物理删除。

## 8. 后续可扩展方向

1. 增加“按行业”模板，例如研发、销售、法务。
2. 增加“按输出目标”模板，例如任务导向、汇报导向、风险导向。
3. 为不同模板增加输出 JSON 结构选项，便于后续自动入库任务系统。
