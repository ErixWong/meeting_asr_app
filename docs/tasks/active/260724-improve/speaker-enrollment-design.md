# 260724 Improve - Speaker Enrollment Design

## 1. 目标

定义声纹识别录入与说话人管理的产品设计，支撑会议中更准确的说话人展示与纪要归属。

## 2. 设计背景

当前原型里已经有“说话人 ID -> 姓名”的映射概念，但这还不是完整的声纹识别产品能力。

正式产品需要解决：

1. 谁来录入声纹。
2. 声纹录入需要多少样本。
3. 未识别说话人如何处理。
4. 声纹数据如何更新、删除和授权。

## 3. 一期产品目标

一期建议做到：

1. 提供独立后台 tab 用于管理说话人条目。
2. 支持录入基础人员信息。
3. 支持采集若干段语音样本并保存。
4. 支持把识别结果映射到真实姓名。
5. 对识别失败或未知说话人提供人工修正回路。

## 4. 角色建议

建议分为：

1. 系统管理员
   - 管理全部声纹配置
2. 纪要管理员
   - 录入、编辑、删除说话人资料
3. 普通用户
   - 查看会议中的说话人映射结果
   - 可临时修正当前会议中的显示名称

## 5. 建议对象模型

### 人员资料

建议字段：

- `id`
- `employee_id`
- `display_name`
- `email`
- `department`
- `title`
- `status`
- `created_at`
- `updated_at`

### 声纹样本

建议字段：

- `id`
- `person_id`
- `sample_name`
- `sample_source`
- `audio_path` 或 `audio_blob_ref`
- `duration_ms`
- `quality_score`
- `status`
- `created_at`

### 声纹特征

是否单独建表，取决于底层引擎如何使用。

如果需要持久化特征，可考虑：

- `id`
- `person_id`
- `feature_type`
- `feature_blob`
- `created_at`

一期如果还没有稳定特征写入方案，可以先只做样本管理和映射管理。

## 6. 录入流程建议

### 路径 A：管理员手工录入

1. 创建说话人资料。
2. 填写姓名、邮箱、部门等信息。
3. 点击“开始录样”。
4. 录入多段样本。
5. 系统做质量检查。
6. 通过后标记为可用。

### 路径 B：会议后补录

1. 会议中出现“未知说话人”。
2. 管理员在会议详情中将其临时命名。
3. 将该未知说话人的片段保存为候选样本。
4. 后台再决定是否转为正式声纹条目。

## 7. 样本采集规则建议

一期建议：

1. 每人至少 3 段样本。
2. 每段建议 5 到 15 秒。
3. 样本内容尽量自然表达，不要完全重复朗读。
4. 每段样本需通过最基本质量校验。

质量校验建议关注：

1. 时长是否足够。
2. 音量是否过低。
3. 是否存在明显静音。
4. 是否存在严重噪音。
5. 是否检测到多人混说。

## 8. 识别结果展示建议

会议中建议按以下优先级展示说话人名称：

1. 已识别且已映射人员：显示真实姓名。
2. 已识别但未映射：显示 `Speaker N`。
3. 置信度过低：显示“待确认说话人”。

## 9. 未知说话人处理

这是产品闭环里的关键设计。

建议支持：

1. 在会议详情页手动把 `Speaker N` 改成姓名。
2. 此修改只作用于当前会议，不默认回写全局声纹库。
3. 管理员可选择“保存为候选说话人”或“合并到已有人员”。

这样可以避免误把一次性判断写进全局库。

## 10. 合规与权限考虑

声纹数据属于敏感数据，建议产品层先明确原则：

1. 仅管理员可查看和管理样本。
2. 普通用户不可导出样本音频。
3. 声纹样本支持删除。
4. 删除后应同步失效关联特征。
5. 需要记录录入人、删除人、更新时间。

## 11. 后台页面建议

建议在独立后台中提供“声纹识别”tab，至少包含以下区域：

1. 人员列表。
2. 人员详情。
3. 样本录入区。
4. 样本列表与质量状态。
5. 候选未知说话人区。
6. 声纹状态与最近更新时间。

## 12. API 建议

建议后续补以下接口：

1. `GET /api/admin/speakers`
2. `POST /api/admin/speakers`
3. `PATCH /api/admin/speakers/:id`
4. `DELETE /api/admin/speakers/:id`
5. `POST /api/admin/speakers/:id/samples`
6. `GET /api/admin/speakers/:id/samples`
7. `DELETE /api/admin/speakers/:id/samples/:sampleId`
8. `POST /api/meetings/:id/speakers/resolve`

## 13. 与会议流程的关系

1. 会中识别结果优先用于实时展示。
2. 会后可以人工修正当前会议中的说话人名称。
3. 会议内修正与全局声纹库更新应拆开处理。

## 14. 一期边界

一期建议不做：

1. 员工自助录入。
2. 企业 HR 系统自动同步人员。
3. 自动增量训练。
4. 大规模声纹批量导入。
5. 跨设备统一质量评分模型。
